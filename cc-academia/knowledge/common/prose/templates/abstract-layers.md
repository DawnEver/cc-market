# Abstract layers

Evidence: user ruling 2026-11-16 (abstract budget), 2026-11-22 (finding first, then value); an approved, unpublished
abstract (2026-11-17); user review 2026-11-23 P2-G7 (general practice). Each layer is one or two sentences; the result
layer holds dimension abstract.result-sentences. Slot shapes: paraphrase; original withheld until publication.

| Layer | Move | Corpus shape (slots, not wording to copy) |
|---|---|---|
| Background | broad application context | [Object class] offer [benefit] for [application]. |
| Object and KPI | the push on the object and why the predicted quantity matters | [Targets] demand [KPI], so [need] grows and [effect] can no longer be neglected. |
| Model | what the paper builds | This paper builds [model] of [object] for [purpose]. |
| Method | analysis framework | [Framework] separates [sources] and traces their [mechanism]. |
| Results | announce, then enumerate findings | The results at [operating point] indicate [number] [findings]. First, [finding], which is [value] in this case. Second, [finding] ([value]). |
| Implication | close on the application | [Effect] should therefore be considered in [design task] of [application]. |

Numbers appear only in the result layer; each value follows its finding (abstract.finding-then-value, where
dimension numbers.abstract-conclusion is finding-then-value). "First, ... Second, ..." enumerates genuinely ordered findings and is
not enumerative scaffolding (argument.no-enumerative-scaffolding targets unordered categories).
